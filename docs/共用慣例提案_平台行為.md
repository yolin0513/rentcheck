# 共用慣例提案：電腦上測不到的平台行為

> 來源：收租紀錄（RentCheck）2026-10-08，CLAUDE.md 規則 12。給統籌工作區的共用慣例用，下面「貼上用」整段可以直接貼。
> 標記：**〔所有平台〕**＝任何瀏覽器、任何手機都要注意；**〔iPhone〕**＝只有 iPhone 的 Safari／主畫面網頁 App（iPhone 上的所有瀏覽器底層都是 Safari）；**〔Safari〕**＝iPhone 和 Mac 的 Safari 都會。

---

## 貼上用

### 電腦上測不到的，不只是視覺，還有平台自己插進來的行為

**現象**：程式沒有寫錯，是平台的預設行為撞上我們的設計。測試多半跑在電腦的 Chromium，那個行為不存在，或者 Chromium 和目標平台對同一行程式的解讀不同——**驗證環境本身會說謊**：測試是綠的、截圖是好的，手機上卻壞了。

**做法**
1. **不模擬平台，改成靜態檢查「有沒有把那個行為關掉或避開」**。關掉它的那一行宣告是讀得到的（例如 `-webkit-user-select: none` 有沒有寫）。每一條檢查都要有對照組，並且**拿出錯的那一版去跑，證明它真的抓得到**；再加一條「把它改壞會紅」的突變。
2. **特別查「Chromium 認、目標平台不認」的寫法**。這種情況下 Chromium 算出來的樣式會騙人（例：不帶前綴的 `user-select: none` 在 Chromium 有效，在 iPhone 無效）。
3. **讓規則守住未來**：會叫出平台行為的程式（例如「按住」的處理）只能在審查過的名單裡，新加的就紅，逼人先對照下面的清單。
4. **每次交件，把「只有實機看得到」的項目明列給使用者確認**，不寫成已驗證。
5. **加新的互動方式之前先對照清單**：長按、拖曳、滑動、雙擊、輸入框、檔案、分享、通知。

**靜態證據判斷不了時間性的行為**：一張截圖看不出那個東西會不會消失、是什麼操作叫出來的。截圖裡出現看不懂的元件時，先問「一直都在嗎？做了什麼之後出現？多久消失？」，再決定要不要為它改版面。不要為一個從截圖推斷出來的限制把版面弄歪。（實例：長按按鈕叫出的 iPhone「書寫工具」，從單張截圖被兩次誤判成常駐的系統元件。）

### 已知清單（有新的就加）

| 平台 | 平台行為 | 撞上什麼 | 避開的做法 |
|---|---|---|---|
| 〔所有平台〕程度不同 | 可以當 emoji 的字元（✔ ◀ ▶ ☎ 📞 📷 ⚠ ⭐…，Unicode `Extended_Pictographic`）可能用彩色 emoji 字型畫，**顏色不吃 CSS 的 `color`**。📞 這類在每個平台都是彩色；✔ ◀ ▶ 這類在 iPhone／Mac 是 emoji、在 Windows／Android 常是單色 | 深色按鈕上的勾變深灰黑、看不見；換主題不跟著變；和文字對不齊 | 圖示一律用 SVG（`currentColor`、大小 1em）。測試掃畫面上不能出現這類字元。加 `U+FE0E` 不可靠，不要當解法 |
| 〔所有觸控平台〕 | 長按一段文字＝選取文字，跳出選取選單（iPhone 還會跳出「書寫工具」、連結預覽） | 要「按住」的按鈕一按住就變成選字 | 按的東西一律關掉文字選取；要按住的元件掛標記（例如 `data-longpress`），靜態檢查它的樣式 |
| 〔Safari〕 | **只認 `-webkit-user-select`**，不帶前綴的 `user-select` 無效；長按選單要另外用 `-webkit-touch-callout: none` 關 | 寫了「不能選取」，iPhone 上等於沒寫 | 兩種寫法一起寫；靜態檢查「寫了一般寫法就必須有帶前綴的」 |
| 〔所有平台〕iPhone 最明顯 | 瀏覽器回報的版本號不可信（Safari 26 起 iOS 版本固定成 18.x；其他瀏覽器也在縮減識別字串） | 依版本號判斷功能一定錯 | 一律功能偵測；靜態檢查擋 `userAgent` 之類 |
| 〔iPhone〕 | 系統「文字大小」不套用到網頁（Android 的 Chrome 多半會套用） | 長輩調大字，App 不變 | App 自己提供字級；Android 上要測「系統字放大」會不會撐破版面 |
| 〔所有手機〕名稱不同 | 「顯示縮放」／「顯示大小」會把 CSS 寬度變窄（iPhone 12：390 → 320） | 一屏放不下、版面擠 | 用最窄的寬度＋最大字測；放不下就捲，不縮字 |
| 〔所有平台〕各不同 | 日期、月份等輸入欄位是原生樣式（iPhone：置中、比別的欄位寬） | 欄位對不齊 | 統一 `appearance`、寬度與對齊；實機確認 |
| 〔iPhone〕有瀏海或動態島的手機都要注意 | 主畫面網頁 App 的狀態列可以疊在內容上（`black-translucent`）；底部有橫條 | 頁首被壓、底部按鈕被蓋 | `viewport-fit=cover`＋`env(safe-area-inset-*)` |
| 〔所有平台〕iPhone 最嚴 | 瀏覽器儲存可能被清掉，**而且沒有任何提示**；iPhone 的主畫面 App 和 Safari 的儲存是分開的 | 資料消失 | 本機只當快取，正本放在使用者自己存的備份檔 |
| 〔所有平台〕清單各不同 | 系統分享面板只收某些檔案類型（iPhone：JSON、ZIP 不行，HTML 可以） | 檔案分享不出去 | 先用 `navigator.canShare({ files })` 檢查；選平台都收的類型 |
| 〔iPhone〕 | 點輸入框時，字小於 16px 會整頁放大 | 畫面突然放大、要自己縮回 | 輸入框字級 ≥ 16px |
| 〔iPhone〕 | 自動把一串數字認成電話號碼、變成可撥打的連結 | 門牌、金額、日期被當成電話，點了跳撥號 | `<meta name="format-detection" content="telephone=no">`；真正要撥的號碼自己寫 `tel:` 連結（這個設定只關自動偵測，不關 `tel:`） |
| 〔所有手機〕行為不同 | 螢幕鍵盤打開時，固定在畫面底部的元件會被頂起或蓋住 | 固定列擋住輸入框 | 有輸入框的畫面不要放固定在底部的元件，或實機確認 |
